## Required behavior

`docs/CONTRACT.md:4,12,26` requires authenticated production operations, fail-closed unconfigured APIs, Supabase-backed user context, role enforcement, and tenant isolation. This review specifically checks that authoritative identity comes from validated Supabase authentication rather than decoded, unverified JWT claims.

For the intended fetch-based implementation, the expected trust boundary is a successful Supabase Auth user verification response (normally `/auth/v1/user`), followed by authoritative membership/role lookup for that verified user. Decoding a JWT is not verification. A signature-valid user's editable `user_metadata` is also not an authoritative membership or privileged-role source. Actual module exports, return shapes, error types, and membership schema must be inspected once available rather than invented by a test substitute.
