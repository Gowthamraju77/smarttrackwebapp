## Ten review checks awaiting the implementation

These are distinct authorization boundaries to inspect and, when credentials
and a disposable test database are supplied, exercise. All ten are **blocked**
pending the schema; they are not executed tests or end-to-end passes.

| # | Check | Evidence required |
| --- | --- | --- |
| 1 | RLS coverage and execution roles | Every tenant-owned table has RLS enabled; application roles do not own tables or bypass RLS. |
| 2 | Membership-based reads | Read policies derive the current user from the trusted authenticated identity and constrain rows to that user's tenant membership. |
| 3 | Insert tenant and role checks | `WITH CHECK` rejects a different tenant and disallowed membership roles, including direct database/API writes. |
| 4 | Update old/new row checks | `USING` and `WITH CHECK` prevent cross-tenant row selection, tenant reassignment, and changes beyond the caller's role. |
| 5 | Delete and membership escalation | Viewer/responder restrictions cannot be bypassed by direct DELETE or self-assigned owner/admin membership. |
| 6 | Table and column privileges | Grants do not expose device-secret hashes, privileged writes, or cross-tenant administrative data through an otherwise permissive entry point. |
| 7 | RPC execution grants | Privileged ingest/administrative RPCs revoke default PUBLIC execution and restrict anon/authenticated callers appropriately; service credentials remain privileged. |
| 8 | SECURITY DEFINER authorization | Each definer function validates caller identity/tenant/role or is restricted to a trusted role; caller-supplied tenant or audit-actor IDs cannot substitute for identity. |
| 9 | SECURITY DEFINER object resolution | Function-local `search_path` is pinned to trusted schemas; relation/type/function resolution cannot be shadowed through writable schemas or implicit `pg_temp` lookup. Explicit qualification and schema CREATE privileges must be considered together. |
| 10 | Cross-tenant relational integrity | Device/telemetry/SOS references cannot combine one tenant's identifier with another tenant's parent row; helper calls and audit writes preserve the same boundary. |
